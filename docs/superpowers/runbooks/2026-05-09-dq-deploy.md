# dq subsystem deploy — Hetzner runbook (2026-05-09)

This runbook brings the dq subsystem (M0–M6 + NG1 + NG6 + Batches 1–3)
live on the Hetzner deploy host. It assumes the existing
`docker compose` deploy at `/home/emersus/aslan-core/infra/deploy/` is
already running (postgres / redis / minio / kap-tail / kap-body-fetcher /
dashboard / api / event-extractor — see workspace `HETZNER_OPS.md`).

The shortest path is **`bash infra/deploy/install-dq.sh`**; the steps
below are the manual breakdown for first-time review and for selective
re-runs.

> **CLI naming note:** the in-repo entrypoint is `aslan` (not
> `aslan-core`) — see `pyproject.toml` `[project.scripts]`. Every
> command in this runbook uses `aslan`. The cron fragment + installer
> follow the same convention.

## Inputs sidar must provide

These are the only manual inputs; everything else is zero-input.

| Env var | What | How to get it |
|---|---|---|
| `ASLAN_PUBLIC_STATUS_DSN` | DSN for `public_status_reader` role | Created by migration 0063; pick a password and put it in the role + here |
| `DQ_GLITCHTIP_DSN` | Sentry-compat DSN | Create a project in GlitchTip on `127.0.0.1:8800` and copy the DSN |
| `DQ_ALERT_SMTP_URL` | SMTP relay URL | e.g. Resend (`smtps://api:RESEND_KEY@smtp.resend.com:465`) or SES |
| `DQ_ALERT_FROM` | Sender address | e.g. `alerts@aslan.terminal` |
| `DQ_ALERT_TO` | Comma-separated recipients | e.g. `sidar@aslan.terminal` |
| `DQ_SLACK_WEBHOOK_URL` | Slack incoming webhook | Slack app → Incoming Webhooks → `#aslan-alerts` |
| `DQ_KAP_LISTING_URL` (optional) | KAP HTTP listing URL | Leave unset for DB-only probes |
| `DQ_MKK_API_URL` / `DQ_MKK_API_KEY` (optional) | MKK VYK API | Leave unset for DB-only probes |

Empty values are tolerated; the relevant sink/probe gracefully suppresses.

## Step 1: native deps (one-time, zero input)

The deploy `Dockerfile` already bakes WeasyPrint's native deps into
the container image (commit *infra(dq): WeasyPrint native deps in
deploy Dockerfile*), so no host-level apt install is required to make
the dq containers render PDFs.

If you want the **host CLI** (`uv run aslan ...` outside docker — used
by the cron entries in `cron.dq`) to also render PDFs, install once on
the host:

```sh
sudo apt update
sudo apt install -y libpango-1.0-0 libpangoft2-1.0-0 \
                    libharfbuzz-subset0 libcairo2 libgdk-pixbuf-2.0-0
```

PDF rendering only fires on the weekly scorecard (Sun 23:55 UTC), so
this is non-blocking for the rest of the deploy.


## Step 4: install cron

```sh
cd ~/aslan-core
crontab -l \
  | grep -v '^# dq subsystem cron' \
  | grep -v 'aslan audit' \
  > /tmp/crontab.before
cat /tmp/crontab.before infra/deploy/cron.dq | crontab -
crontab -l | grep -E 'aslan audit|dq subsystem'   # sanity check
```

(Or just run `bash infra/deploy/install-dq.sh`.)

```sh
    bloomberg-claim-check --field filing_lag_p95_30d
```

## Step 7: NG1 public deployment (optional, when ready)

The `public-status` container binds `127.0.0.1:8081` on the host. To
expose it publicly:

1. **DNS:** point `status.aslan.<domain>` → Hetzner public IPv4.
2. **TLS termination:** add a Caddy / nginx vhost on the host that
   proxies `https://status.aslan.<domain>` → `http://127.0.0.1:8081`,
   with Let's Encrypt.
3. **CDN (optional):** front the vhost with Cloudflare; the page
   already sets `Cache-Control: public, max-age=60` so caching just
   works.
4. **External uptime probe:** UptimeRobot / Better Uptime / similar
   pointed at `https://status.aslan.<domain>/status` on a 30s
   interval.

None of step 7 blocks the rest of the dq deploy — internal tunnel
(`ssh -L 8081:localhost:8081 hetzner`) is enough for sidar / ops use.

## Rollback

```sh
cd ~/aslan-core/infra/deploy
docker compose stop dq-alert-dispatch public-status
docker compose rm -f dq-alert-dispatch public-status

# Strip dq cron entries
crontab -l \
  | grep -v '^# dq subsystem cron' \
  | grep -v 'aslan audit' \
  | crontab -
```

Migrations are not rolled back automatically — they're additive
(new schemas/tables only) and harmless when the dq services are
stopped. If you genuinely need to drop dq schema, do it manually.

## Where to look when something breaks

| Symptom | Where |
|---|---|
| Cron job didn't fire | `tail -100 /tmp/dq-<job>.log` |
| Alert dispatcher silent | `docker logs --tail 200 aslan-dashboard-dq-alert-dispatch-1` |
| Public status 5xx | `docker logs --tail 200 aslan-dashboard-public-status-1` |
| Slack/email/glitchtip not delivering | `docker compose exec dashboard /app/.venv/bin/aslan audit test-alert --sink <name>` |
| Coverage / recency stale | `docker compose exec dashboard /app/.venv/bin/aslan audit recency-sweep` (forces a sweep) |
